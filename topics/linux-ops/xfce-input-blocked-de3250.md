# XFCE でキー／クリックが効かなくなる（DE3250）

- **機種:** [`aopen-de3250`](../environments/machines/aopen-de3250.md)
- **環境:** Debian 13 + XFCE（X11）。ローカル操作と xrdp の両方で再現
- **確認日:** 2026-09-19
- **生ログ:** [`inbox/raw/1`](../../inbox/raw/1)、[`inbox/raw/２`](../../inbox/raw/２)

## 症状

- フリーズではない（画面は動く。`Ctrl+Alt+Del` は効く）
- キーボード入力が全体で受け付けられない
- トラックポイントの移動は可能。デスクトップのアイコンのダブルクリックでファイル／アプリは開ける
- パネルの「アプリケーション」、各アプリのメニューバーはクリックしても反応しない
- ローカルでも RDP でも同じ状態になる

## 結論（確定）

**主因は XFCE のキーショートカット設定。** 競合・誤割り当て・修飾キー絡みのショートカットが、入力やメニュー操作を奪う状態になっていた。

対処の軸はショートカットの見直し・無効化（設定 → キーボード → アプリケーションショートカット、およびウィンドウマネージャのショートカット）。どのキー割り当てが直接の犯人かは、必要なら再発時に個別にメモする。

## 切り分けで分かったこと

| 観察 | 意味 |
|------|------|
| `Ctrl+Alt+Del` が効く | カーネル全体の死ではない |
| ポインタは動くがキー／メニューが死ぬ | セッション／入力フォーカス側 |
| ローカルと RDP の両方 | 単体の xrdp 障害だけでは説明しにくい |
| デスクトップのダブルクリックだけ効く | 全面フリーズではなく、入力の独占／干渉パターン |

## 試したが主因ではなかった／当てはまらなかったもの

初期の AI 助言には **EliteDesk 800 G5 向けの想定が混ざっていた**（実機は DE3250）。次は優先度が低い、またはこの案件では主因ではなかった。

- USB `autosuspend` / `i915.enable_psr` などの GRUB パラメータ（DE3250・Valleyview には当てはまりにくいものあり）
- コンポジタ（この機では既に OFF だった）
- カーネル差し替えや Wayland 移行（恒久策の候補にはなりうるが、本件の主因ではなかった）
- 見えないダイアログ／IBus 単独など（切り分け候補としては妥当だが、最終結論はショートカット）

`hypothesis:` 2026-09-19 — light-locker の起動時クラッシュは別件のノイズの可能性。入力不能の主因としては扱わない。

## 再発時の短い手順

1. XFCE のキーボード／ウィンドウマネージャのショートカットを確認し、怪しい割り当てを外す
2. それでも戻らなければ TTY（`Ctrl+Alt+F3`）からセッション再起動: `pkill -u $USER xfce4-session`
3. grab 調査が必要なら: `DISPLAY=:0 xdotool key XF86LogGrabInfo` → `/var/log/Xorg.0.log` の grab 行
